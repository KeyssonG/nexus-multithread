Changelog — Portal Multithread

ago/2026

Resumo executivo

Conjunto de entregas concluído entre os dias 2 e 4 de agosto de 2026 no Portal Multithread, um sistema de gestão empresarial que atende a múltiplas empresas sobre um mesmo banco. O trabalho envolveu a construção de um módulo completo de gestão de estoque no backend e no frontend, a correção do isolamento de dados por empresa, a adoção de Redis como camada de cache, a evolução do fluxo de implantação para um repositório GitOps sincronizado via ArgoCD e a criação de um serviço de backup automático do PostgreSQL com notificação por e-mail. Todas as etapas foram validadas por compilação e por execução no ambiente de produção (Kubernetes).

detalhes

1 Backend — módulo de estoque

nexus-multithread · Spring Boot 3.4.4 · JdbcTemplate
  • API REST completa sob /estoque (40+ endpoints)
  • Centros, localizações, produtos, categorias e movimentações
  • Inventário, dashboard e relatórios (valor e giro)
  • DTOs como records Java, RowMapper e soft delete
detalhes

2 Frontend — módulo de estoque

api-multithread · React 19 · TypeScript · Vite
  • Telas de centros, produtos, categorias e movimentações
  • Dashboard com indicadores, inventário e relatórios
  • Validação de acesso por módulo a partir do JWT
  • Contrato snake_case entre frontend e backend
detalhes

3 Multitenancy por empresa

Migração id_empresa no PostgreSQL
  • id_empresa em 7 tabelas do módulo, com FK e índice
  • Chaves UNIQUE compostas por empresa
  • Empresa extraída do token JWT em toda consulta
  • Dados de empresas diferentes nunca se misturam
detalhes

4 Infra declarativa (GitOps)

k8s-gitops · ArgoCD · K3s
  • Manifestos versionados em repositório GitOps dedicado
  • Redis, RabbitMQ e ConfigMap sincronizados via ArgoCD
  • Eliminado o loop de builds do Jenkins
  • Aplicação do cluster 100% declarativa
detalhes

5 Cache com Redis

Consulta de categorias · TTL 20 min
  • Padrão cache-aside na consulta de categorias
  • Chave por empresa: estoque:categorias:{idEmpresa}
  • Uma leitura no GET e uma escrita no miss
  • Redis indisponível não interrompe a consulta
detalhes

6 Backup do PostgreSQL

backup-postgres-service · Python 3.12
  • pg_dump periódico com push para repositório Git privado
  • Retenção automática de 7 dias
  • Notificação por e-mail de sucesso e de falha
  • Integração RabbitMQ + msgsend-service

Principais resultados

Módulo de estoque
Backend e frontend completos, do modelo de dados aos relatórios, com regras de negócio e auditoria via JWT.
Multitenancy
Isolamento por empresa em todas as consultas e gravações do módulo, com unicidade respeitando a empresa.
Infra como código
Cluster gerenciado por manifestos GitOps com sincronização automática via ArgoCD e sem credenciais versionadas.
Cache em produção
Redis integrado à aplicação e à configuração do cluster, com queda de custo de consulta e TTL controlado.
Resiliência de dados
Backup automatizado do banco de produção com retenção e alertas por e-mail para cada ciclo.
